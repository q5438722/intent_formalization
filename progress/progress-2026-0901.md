# Weekly Progress: Completeness of Rust Slice Specifications

Snapshot: 2026-09-01 11:02 UTC

Due to Argus's regression bug, only the Slice module was evaluated in this week.

## 1. Result categories

- **Complete**: output is deterministic without a trust boundary.
- **Conditional complete**: output is deterministic with trust boundaries.
- **Incomplete**: the same input and trust boundary permit different outputs.
- **Unknown**: insufficient for classification.

## 2. Current Slice results

The Slice catalog contains 132 stable APIs: 120 generated specifications and
12 exact-vstd specifications. The current completeness accounting below covers
the 120 generated specifications and reports only exact-output results.

| Conditional complete | 49 |
| Incomplete | 11 |
| Unknown (`missing-source-backed-model`) | 2 |
| Not run | 0 |
| **Total generated specifications** | **120** |

## 3. Representative Slice cases

### 3.1 `sort_unstable`: exact-output incomplete


```rust
pub assume_specification<T: core::cmp::Ord>[
    <[T]>::sort_unstable
](
    slice: &mut [T],
)
    ensures
        slice_permutation(old(slice)@, final(slice)@),
        slice_sorted_by_ord(final(slice)@),
;
```

`slice_sorted_by_ord` does not constrain the relative order of elements that
are equivalent under `Ord`: neither element is less than or greater than the
other. These elements may therefore be exchanged while both
`slice_permutation` and `slice_sorted_by_ord` remain true, so the exact output
is incomplete.

### 3.2 `splitn_mut`: conditional complete

```rust
pub assume_specification<'a, T, F: core::ops::FnMut(&T) -> bool>[
    <[T]>::splitn_mut::<F>
](slice: &'a mut [T], n: usize, pred: F) -> (iter: core::slice::SplitNMut<'a, T, F>)
    ensures slice_predicate_split_view::<core::slice::SplitNMut<'a, T, F>, F, T>(
        iter, old(slice)@, pred, false, false, n as int),
;
```

`splitn_mut` only constructs a lazy iterator and does not call `pred`.
Its trust boundary ensures:

- the input slice's allocation identity, ensuring that both executions refer
  to the same underlying memory;
- the mutable-borrow identity, ensuring that the returned iterators hold the
  same borrow rather than borrows of different slices with equal contents;

The source constructor chain then uniquely determines:

- which slice the iterator references;
- the remaining unvisited range;
- the maximum number of splits, `n`;
- the predicate's initial state;
- the other initial fields of `SplitMut` and `SplitNMut`.

The output is therefore `COMPLETE`.

### 3.3 `select_nth_unstable_by`: unknown

```rust
pub assume_specification<T, F: core::ops::FnMut(&T, &T) -> core::cmp::Ordering>[
    <[T]>::select_nth_unstable_by::<F>
](slice: &mut [T], index: usize, compare: F) -> (ret: (&mut [T], &mut T, &mut [T]))
    requires index < old(slice)@.len(),
    ensures
        final(slice)@ == final(ret.0)@ + seq![*final(ret.1)] + final(ret.2)@,
        final(ret.0)@.len() == index,
        *final(ret.1) == final(slice)@[index as int],
        final(ret.2)@.len() == old(slice)@.len() - (index as int) - 1,
        slice_permutation(old(slice)@, final(slice)@),
        slice_select_partition_cmp(final(ret.0)@, *final(ret.1), final(ret.2)@,
            comparator_observation(compare, old(slice)@)),
;
```

For slices of length at most four, the implementation uses insertion sort, which has been modeled and verified. For longer slices, it is similar to quicksort: pivot selection is determined arbitrarily and comparison order is determined dynamically as the partition evolves. 
This path is difficult to verify directly and requires a separate recursion invariant covering pivot
selection, partitioning, range narrowing, and comparator state. The result therefore remains `Unknown`.

## 4. Main findings

Percentages below use all 120 generated Slice specifications as the
denominator.

1. **Most specifications are complete or conditional complete: 107/120 (89.2%).**  
2. **Some APIs naturally permit exact-output incompleteness: 11/120 (9.2%) are currently classified Incomplete.**  
3. **Only a small number remain Unknown: 2/120 (1.7%).**  

4. **Completeness checking can provide feedback for specification
   generation.**  
   For example, `binary_search_by` was initially classified as Incomplete
   because its generated precondition did not require a sorted input. With the incomplete feedback, it adds the intended ordering requirement, and thus becomes complete.
