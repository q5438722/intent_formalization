# Weekly Progress: Re-evaluating Rust Specification Completeness

Snapshot: 2026-09-15 12:13 UTC

## 1. Re-evaluating Slice and Vec completeness

We rechecked the Rust 1.96 Slice and Vec specifications at four levels: completeness on the raw output values, completeness on the views of outputs, adding `Equivalent fn` on the views of outputs, repairing specs to eliminate the rest incompleteness.

| Module  | Raw-value completeness | View-level completeness | With `Equivalent fn` | After repairing specification |
| --- | --- | --- | --- | --- |
| Slice, 130 functions | 73 complete, 3 incomplete, 54 unknown | 87 complete (66.9%), 43 incomplete | 98 complete (75.4%), 32 incomplete | **130 complete (100.0%)** |
| Vec, 49 functions | 37 incomplete, 12 unknown | 28 complete (57.1%), 20 incomplete, 1 unknown | 29 complete (59.2%), 19 incomplete, 1 unknown | **49 complete (100%)** |

- View-level comparison removes low-level details, e.g., the ownership of mutable references.
- `Equivalent Fn` handles multiple legal choices; for example, `Vec::shrink_to_fit` may return different source-valid capacities.
- The repair stage then strengthened the remaining incomplete specs.

## 2. Specification-repair case studies

### 2.1 `Vec::shrink_to`

Original vstd specification:

```rust
pub assume_specification<T, A: Allocator>[ Vec::<T, A>::shrink_to ](
    v: &mut Vec<T, A>,
    min_capacity: usize,
)
    ensures
        final(v)@ == old(v)@,
        final(v).spec_capacity() >= old(v)@.len(),
        final(v).spec_capacity() <= old(v).spec_capacity(),
;
```

The spec ignores `min_capacity` and the no-op case. With
`length = 3`, `min_capacity = 4`, and `old_capacity = 5`, it should admit final
capacities 3 and 4, and reject capacity 5.

The repair adds the missing lower bound and no-op branch. Different capacities
inside the valid interval remain equivalent under `Equivalent_shrink_to`:

```rust
pub assume_specification<T, A: Allocator>[ Vec::<T, A>::shrink_to ](
    v: &mut Vec<T, A>,
    min_capacity: usize,
)
    ensures
        final(v)@ == old(v)@,
        final(v).spec_capacity() >= old(v)@.len(),
        final(v).spec_capacity() <= old(v).spec_capacity(),
        old(v).spec_capacity() > min_capacity as nat
            ==> final(v).spec_capacity() >= min_capacity as nat,
        old(v).spec_capacity() <= min_capacity as nat
            ==> final(v).spec_capacity() == old(v).spec_capacity(),
;
```

### 2.2 `slice::get_mut`

Original generated specification:

```rust
#[verifier::allow(undeclared_external_trait)]
pub assume_specification<T, I>[ <[T]>::get_mut::<I> ](
    slice: &mut [T],
    index: I,
) -> (ret: Option<&mut <I as core::slice::SliceIndex<[T]>>::Output>)
    where I: core::slice::SliceIndex<[T]>
    ensures
        ret.is_some() ==> slice_index_in_range(old(slice)@, index)
            && slice_index_mut_frame(old(slice)@, index, final(slice)@),
        ret.is_none() ==> !slice_index_in_range(old(slice)@, index)
            && final(slice)@ == old(slice)@,
;
```

The spec fixes only the `Some`/`None` variant. It does not require `ret` pointing to
the selected region, or keep the values from other indexes.

If we define `index` as `[lo, hi)`, the specification should be:

```text
initial_view(ret) = old(slice)@[lo .. hi)
relative_range(ret) = [lo, hi)
len(final_view(ret)) = hi - lo
final(slice) =
    old(slice)@[0 .. lo)
    + final_view(ret)
    + old(slice)@[hi .. old(slice).len())
```

Repaired specification:

```rust
#[verifier::allow(undeclared_external_trait)]
pub assume_specification<T, I>[ <[T]>::get_mut::<I> ](
    slice: &mut [T],
    index: I,
) -> (ret: Option<&mut <I as core::slice::SliceIndex<[T]>>::Output>)
    where I: core::slice::SliceIndex<[T]>
    ensures
        ret.is_some() ==> slice_index_in_range(old(slice)@, index)
            && slice_index_result(
                old(slice)@,
                index,
                &*ret.unwrap(),
            )
            && slice_index_returned_range(
                old(slice)@,
                index,
                ret.unwrap(),
            )
            && slice_index_mut_writeback(
                old(slice)@,
                index,
                ret.unwrap(),
                final(ret.unwrap()),
                final(slice)@,
            ),
        ret.is_none() ==> !slice_index_in_range(old(slice)@, index)
            && final(slice)@ == old(slice)@,
;
```


## 3. Tooling and broader evaluation

We refactored [`spec-completeness-checking`](https://github.com/q5438722/spec-completeness-checking),
integrated test cases from VeruSAGE, and made the tool ready for release:

- separated the LLM-independent checker from optional LLM-assisted fallback;
- modularized spec extraction, view/equivalence modeling, completeness checking,
  proof generation, proof checking, and reporting;
- removed the previous VeruSAGE/Nanvix-specific code and added a standalone
  CLI with reproducible artifacts and replay;
- retained Verus as the first backend while leaving an interface for future
  support of other verification languages, such as Dafny.

I asked a junior student to evaluate specification completeness
in Verismo and Asterinas. He has reported five preliminary Verismo issues; I
will double-check with him and report them in our discuss channel.
